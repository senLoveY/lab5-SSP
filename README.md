# Лабораторная работа: Многопоточное и асинхронное программирование в C#

## 🎯 Цели работы
1. Реализация потокобезопасного паттерна **«Producer-Consumer»** (Производитель-Потребитель).
2. Изучение и применение примитивов синхронизации: `SemaphoreSlim` и `Mutex`.
3. Моделирование ситуации **Deadlock** (взаимоблокировки) и её визуальная диагностика средствами Visual Studio.
4. Предотвращение тупиков с помощью унификации порядка блокировок и метода `Monitor.TryEnter`.
5. Синхронизация между независимыми процессами (приложениями) на уровне ОС Windows с использованием именованного **Global Mutex**.

---

## 🏗 Структура проекта

Весь код разделен на 5 логических файлов (классов) для удобства навигации и соблюдения принципов ООП. Запуск модулей осуществляется через интерактивное консольное меню в главном файле программы.

* `Program.cs` — Главная точка входа. Реализует интерактивное меню (выбор частей лабораторной).
* `Part1ProducerConsumer.cs` — Реализация паттерна Producer-Consumer (3 производителя, 4 потребителя, передача объектов `DataItem`, использование семафоров).
* `Part2DeadlockOriginal.cs` — Специально спроектированный код с перекрестным захватом ресурсов (`lock`), гарантированно вызывающий зависание (Deadlock) для отладки.
* `Part2DeadlockFixed.cs` — Исправленный вариант предыдущего кода, исключающий тупики за счет одинакового порядка захвата мониторов и использования таймаутов.
* `Part3Mutex.cs` — Использование глобального именованного мьютекса (`Global\MyAppMutex`) для предотвращения одновременной работы двух экземпляров программы.

## 🚀 Инструкция по запуску и проверке

### Подготовка
1. Откройте решение (`.sln`) в **Visual Studio**.
2. Убедитесь, что выбран режим конфигурации **Debug**.
3. Нажмите `F5` для запуска приложения в режиме отладки.

### Часть 1. Producer-Consumer
* В главном меню введите `1` и нажмите `Enter`.
* Вы увидите асинхронный лог добавления и извлечения объектов `DataItem` из общей очереди.

### Часть 2. Диагностика Deadlock (Зависание)
* В главном меню введите `2`.
* Программа преднамеренно **зависнет**. 
* **Для диагностики:** в Visual Studio нажмите кнопку **«Пауза»** (Прервать все / `Ctrl+Alt+Break`). 
* Перейдите в меню `Отладка -> Окна -> Параллельные стеки` (Debug -> Windows -> Parallel Stacks) для просмотра графа заблокированных потоков.
* Нажмите «Остановить отладку» (Stop Debugging), чтобы закрыть программу.

### Часть 2 (Исправленная). Запуск без зависаний
* Запустите программу (`F5`) и выберите пункт `3`.
* Потоки корректно отработают с применением `Monitor.TryEnter` (выводя уведомление о таймауте, но не зависая навсегда).

### Часть 3. Межпроцессный Mutex
* Выберите пункт `4`. Мьютекс будет захвачен первым окном программы. **Не нажимайте Enter**.
* Перейдите в папку скомпилированного проекта (`\bin\Debug\net...`) и запустите `*.exe` файл напрямую из проводника (откроется второе окно).
* Во втором окне также выберите пункт `4`. Вы получите сообщение об ошибке: *"Не удалось захватить мьютекс (уже запущен другой экземпляр)"*.
